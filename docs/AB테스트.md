# A/B 테스트 — 친근한 톤 vs 전문적인 톤

> 보너스 과제. 같은 주제·같은 모델로 톤만 바꿔 두 벌을 만들고 비교했습니다.

```bash
python main.py --topic "가을에 걷기 좋은 성지순례길" --ab
```

- 주제: `가을에 걷기 좋은 성지순례길`
- 모델: Gemini (`gemini-flash-lite-latest`)
- 생성: 3개 플랫폼 × 2개 톤 = **6건** (실패 0건)
- 결과 원본: [`samples/콘텐츠.md`](../samples/콘텐츠.md)

---

## 1. 톤이 실제로 갈렸는가 — 어미 분포

| 톤 | `~요.` 로 끝난 문장 | `~다.` / `~니다.` 로 끝난 문장 |
| --- | ---: | ---: |
| A안 (친근) | **17** | 3 |
| B안 (전문) | 2 | **13** |

프롬프트에 적은 한 줄(`'~해요' 체로 다정하게` / `'~합니다' 체로 신뢰감 있게`)이
그대로 반영됐습니다. **톤 지시는 어미 수준까지 먹힙니다.**

---

## 2. 같은 내용을 어떻게 다르게 말했나

### 인스타그램 캡션 끝문장

| A안 (친근) | B안 (전문) |
| --- | --- |
| "누구나 편안하게 발걸음을 옮길 수 있는 고요한 **쉼터가 되어드릴게요.**" | "깊어가는 계절의 풍경 속에서 온전한 쉼을 **경험해보시기 바랍니다.**" |

A안은 **서비스가 화자**로 나서서 약속합니다("되어드릴게요").
B안은 **정보를 건네고 물러섭니다**("소개합니다", "~시기 바랍니다").

### 구체적 숫자를 쓰는가

B안만 브랜드의 사실을 끌어왔습니다.

> B안: "**가톨릭 성지 208곳 중** 누구나 편히 쉬어가며 걸을 수 있는…"
> A안: (숫자 없음)

같은 브랜드 설명을 넣었는데 A안은 감성을 택했고 B안은 근거를 택했습니다.

### 해시태그 성격이 갈렸다

| A안 (친근) | B안 (전문) |
| --- | --- |
| #힐링여행 #가을풍경 **#여행에미치다** **#마음쉼터** | #트레킹 **#순례길** #걷기좋은길 #산책 |

A안에는 **커뮤니티·감성 태그**가 섞였습니다(`#여행에미치다` 는 인스타 여행 커뮤니티 태그).
B안은 **검색해서 찾아올 말**로 채웠습니다.

지시하지 않은 차이입니다. 톤 한 줄이 해시태그 선택까지 밀고 갔습니다.

## 3. 규격은 둘 다 지켰다

| 항목 | A안 | B안 | 규격 |
| --- | ---: | ---: | --- |
| 인스타 캡션 | 134자 | 128자 | 150자 내외 ✅ |
| 인스타 해시태그 | 10개 | 10개 | 10개 내외 ✅ |
| 블로그 본문 | 709자 | 574자 | 500자 이상 ✅ |
| 블로그 소제목 | 4개 | 3개 | 3개 이상 ✅ |
| X 길이 | 127자 | 136자 | 280자 이내 ✅ |

**톤을 바꿔도 규격은 흔들리지 않습니다.** 규격과 톤을 프롬프트의 다른 칸에 나눠 둔 덕입니다.

### 다만 A안 블로그에서 하나가 어긋났다

| | 제목 | 실제 소개한 성지 |
| --- | --- | ---: |
| A안 | "…성지순례길 **3곳**" | **2곳** (서소문·솔뫼) |
| B안 | "…추천 **3곳**" | **3곳** (서소문·솔뫼·여주) |

A안은 도입·마무리를 소제목으로 쓰느라 성지 하나를 빼먹었습니다.
같은 프롬프트인데 갈렸습니다 → **프롬프트로는 못 막습니다. 세는 코드가 필요합니다**
([프롬프트 문서](프롬프트-템플릿.md)의 v4 항목).

## 4. 결론 — 어디에 무엇을 쓸 것인가

| 플랫폼 | 권장 | 이유 |
| --- | --- | --- |
| **인스타그램** | **A안 (친근)** | 커뮤니티 해시태그가 도달을 넓힌다. 스크롤 중 멈춰 세우는 건 감성 쪽 |
| **블로그** | **B안 (전문)** | 검색으로 들어오는 글이다. "208곳" 같은 구체적 사실이 신뢰와 체류를 만든다 |
| **X** | **A안 (친근)** | 타임라인에서 스쳐 지나간다. 말 거는 문장이 반응을 얻는다 |

### 주제에 따라서도 갈린다

| 주제 성격 | 권장 톤 | 근거 |
| --- | --- | --- |
| 계절·감성 (가을 걷기, 힐링) | 친근 | 이번 테스트에서 A안이 "산책 같은 순례" 같은 표현을 냈다 |
| 정보·안내 (미사 시간, 교통) | 전문 | 사실을 다루는 글에 "~해드릴게요" 는 가볍게 읽힌다 |
| 역사·순교사 | 전문 | 무게가 필요한 소재다 |

### VisitHolyKorea 에는 이렇게 쓴다

브랜드 원칙이 *"신앙을 앞세우지 않고 쉼과 걷기를 먼저"* 이고,
타겟이 **40-70대 신자 + 20-30대 비신자**로 갈립니다.

- **비신자를 향한 채널(인스타·X)** → 친근한 톤. 문턱을 낮추는 게 목적
- **신자와 검색 유입(블로그)** → 전문적인 톤. 정보의 정확성이 목적

두 톤을 매번 다 뽑아 두고 채널별로 골라 쓰는 것이 낫습니다.
`--ab` 한 번이면 6건이 나오므로 비용도 두 배일 뿐입니다.

---

## 5. 이 테스트의 한계

정직하게 적어 둡니다.

- **실제 반응을 측정한 게 아닙니다.** 도달·좋아요·클릭을 재지 않았습니다.
  여기 결론은 *"글이 어떻게 다른가"* 까지이고, *"어느 쪽이 더 잘 먹히는가"* 는
  실제로 올려 보고 지표를 봐야 압니다.
- **주제 1개, 실행 1회입니다.** 모델은 같은 프롬프트에도 매번 다르게 답합니다.
  A안 블로그가 성지를 2곳만 낸 것도 그날의 편차일 수 있습니다.
- 제대로 하려면 주제 5개 × 톤 2개 × 3회씩 돌려 평균을 봐야 합니다.
  이 워크플로우는 `--topic` 만 바꿔 반복하면 되므로 그 확장은 어렵지 않습니다.
