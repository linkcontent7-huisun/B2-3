# 워크플로우 구조와 단계별 역할

![워크플로우 구조](workflow.png)

> 위 그림은 [`make_diagram.py`](make_diagram.py) 로 그립니다. 노코드 툴 캔버스를 찍은
> 스크린샷 대신 코드로 남긴 이유는, 워크플로우가 바뀌면 그림도 같이 갱신되게 하기 위해서입니다.

---

## 단계별 역할

| 단계 | 하는 일 | 담당 파일 | 실패하면 |
| --- | --- | --- | --- |
| **[1] 주제 입력** | 주제를 받아 워크플로우를 트리거 | `main.py` | 빈 값이면 다시 묻는다 |
| **[2] 텍스트 생성** | 플랫폼 × 톤 조합마다 LLM 호출 | `platforms.py` + `pipeline.py` | 그 조합만 건너뛰고 계속 |
| **규격 검증** | 글자 수·해시태그 수를 세어 확인 | `pipeline.check_format` | 결과에 ⚠️ 로 표시 |
| **[3] 대표 이미지** | 영어 장면 묘사 → 이미지 API → PNG | `pipeline.build_image_prompt` / `generate_image` | 텍스트만 남기고 계속 |
| **[4] 저장** | 플랫폼별로 구분해 파일로 | `pipeline.save` | — |
| 노션 업로드 | 팀이 함께 보는 페이지로 | 수동 (아래 참고) | — |

## 연결 구조 — 왜 이 순서인가

### 설정이 [1] 보다 먼저 들어간다

`config.json` 의 **브랜드 설명**이 [2]와 [3] 프롬프트의 문맥이 됩니다.
브랜드를 안 넣으면 모델이 브랜드 톤을 알 도리가 없습니다
(실제로 초안에서 "은혜가 가득한" 이라는 종교 권유 표현이 나왔습니다 —
[프롬프트 문서](프롬프트-템플릿.md) 참고).

API 키는 `config.json` 이 아니라 `.env` 에 둡니다.
`config.json` 은 저장소에 올라가는 파일이라, 키를 적으면 그대로 공개됩니다.
설정에는 **어느 환경 변수를 볼지**만 적습니다.

```jsonc
"ai": { "api_key_env": "GEMINI_API_KEY" }   // ← 키가 아니라 '변수 이름'
```

### [2]와 [3]이 갈라졌다가 [4]에서 합쳐진다

텍스트와 이미지는 서로를 기다릴 이유가 없습니다.
**이미지 API 가 막혀도 텍스트는 남아야 하고, 그 반대도 마찬가지입니다.**

그래서 각 단계는 실패를 `result.errors` 에 기록만 하고 다음으로 넘어갑니다.
마지막에 무엇이 빠졌는지 결과 파일에 함께 남습니다.

```
⚠️ 1개 단계가 실패했습니다.
   - 이미지 생성: 이미지 생성 실패: HTTP 429
```

### 규격 검증이 [2] 뒤에 따로 붙는다

프롬프트에 "280자 이내" 라고 적어도 모델은 넘깁니다.
**부탁한 것과 지켜진 것은 다릅니다.** 그래서 세는 단계를 따로 뒀습니다.

| 플랫폼 | 세는 것 |
| --- | --- |
| 인스타그램 | 해시태그 8~12개인가 |
| 블로그 | 본문 500자 이상인가, 소제목 3개 이상인가 |
| X | 280자를 넘지 않았는가 |

어긋나면 버리지 않고 **표시만 합니다.** 사람이 보고 판단할 문제이기 때문입니다.

### 이미지는 두 번에 나눠 만든다

```
[한국어 주제] → LLM("영어 20단어로 장면 묘사") → [영어 장면] → 이미지 API → PNG
```

한국어를 이미지 API 에 그대로 넘기면 엉뚱한 그림이 나옵니다.
A2-1 과제에서 `"20-30대 여성"` 을 인물 사진 요청으로 읽어 사람 사진이 나온 적이 있습니다.
LLM 이 **기획**하고 이미지 API 가 **렌더링**하는 구조입니다.

## 실행

```bash
python main.py                                       # 대화형
python main.py --topic "가을에 걷기 좋은 성지순례길"   # 비대화형
python main.py --topic "..." --ab                    # [보너스] 친근 vs 전문 두 버전
python main.py --topic "..." --no-image              # 텍스트만
```

결과는 `output/날짜-주제/` 에 쌓입니다.

```
output/20260820-가을에-걷기-좋은-성지순례길/
├── 콘텐츠.md      ← 사람이 읽고 그대로 복사해 붙일 것
├── result.json    ← 기계용 (다음 단계에서 읽어 쓸 수 있게)
└── cover.png      ← 대표 이미지
```

## 노션에 올리기

명세가 *"생성된 텍스트와 이미지를 노션 등 협업 도구에 자동 저장"* 을 요구합니다.
이 워크플로우는 `콘텐츠.md` 를 노션이 그대로 알아듣는 마크다운으로 냅니다.
**노션 페이지에 붙여 넣으면 소제목·인용·코드블록이 그대로 살아납니다.**

완전 자동으로 올리려면 노션 통합 토큰이 필요합니다. 붙이는 자리는 이미 비워 두었습니다.

```python
# pipeline.save() 뒤에 한 단계만 더하면 된다
# notion.create_page(parent_id, title=result.topic, markdown=render_markdown(result))
```

토큰을 만들면 `.env` 에 `NOTION_TOKEN` 으로 넣고, `config.json` 에
`"notion": {"token_env": "NOTION_TOKEN", "parent_page_id": "..."}` 를 추가하는 구조입니다.
지금 단계에서 넣지 않은 이유는, 토큰 없이도 워크플로우 전체가 돌아가야 하기 때문입니다.

## 노코드 툴(n8n / Make)로 옮기려면

이 파이프라인은 노드 4개짜리 워크플로우와 1:1로 대응합니다.

| 이 프로젝트 | n8n 노드 |
| --- | --- |
| `main.py` 의 주제 입력 | **Form Trigger** (주제 입력 폼) |
| `platforms.py` × `pipeline.generate_texts` | **HTTP Request** 3개 (플랫폼별 Gemini 호출) |
| `pipeline.check_format` | **Code** 노드 (글자 수 세기) |
| `pipeline.build_image_prompt` + `generate_image` | **HTTP Request** 2개 (장면 묘사 → 이미지) |
| `pipeline.save` | **Notion** 노드 |

옮길 때 그대로 쓸 수 있도록, 프롬프트 전문을
[프롬프트 문서](프롬프트-템플릿.md)에 복사 가능한 형태로 남겨 두었습니다.
