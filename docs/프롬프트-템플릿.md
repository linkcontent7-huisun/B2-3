# 프롬프트 템플릿 설계

플랫폼별 프롬프트를 어떻게 설계했는지, 그리고 **왜 그렇게 고쳤는지**를 남깁니다.
모든 예시는 실제로 돌려 얻은 출력입니다. 지어낸 것이 없습니다.

- 주제: `가을에 걷기 좋은 성지순례길`
- 브랜드: VisitHolyKorea (한국 가톨릭 성지 208곳 순례 안내 서비스)
- 모델: Gemini (`gemini-flash-lite-latest`)

---

## 프롬프트 구조

세 플랫폼이 **같은 뼈대**를 씁니다. 칸만 바뀝니다.
순서를 고정해 두면 결과가 나쁠 때 어느 칸을 고칠지 바로 짚을 수 있습니다.

```
[역할]        당신은 소셜 미디어 콘텐츠 에디터입니다.
[브랜드]      ← config.json 의 brand. 톤과 금지어의 근거
[주제]        ← 사용자 입력
[플랫폼]      ← platforms.py 의 규격 (글자 수, 해시태그 수, 구조)
[톤앤매너]    ← friendly / professional
[공통 규칙]   한국어 · 사실 지어내지 않기 · 종교 권유 금지
[출력 형식]   지정된 JSON 만
```

구현: [`social_content/platforms.py`](../social_content/platforms.py) 의 `build_prompt()`

---

## 초안 → 수정 → 최종

### v1 초안 — "써줘"만 했다

```
가을에 걷기 좋은 성지순례길에 대한 블로그 글을 써줘.
```

세 플랫폼 모두 같은 방식으로 요청했습니다. 실제 출력:

| 플랫폼 | 결과 | 문제 |
| --- | --- | --- |
| 인스타그램 | 172자 · 해시태그 **5개** | 캡션이 길고 해시태그가 절반 |
| 블로그 | **435자 · 소제목 0개** | 500자 미달, 구조가 아예 없음 |
| X | 101자 | 길이는 통과했으나 브랜드 언급 없음 |

**출력에서 그대로 옮긴 문장:**

> "이번 주말, 가을 나들이로 걸음마다 **은혜가 가득한** 성지순례길 어떠신가요?"

두 가지가 한꺼번에 어긋났습니다.

1. **규격 미달** — 플랫폼마다 다른 형식 요구를 아예 모릅니다.
2. **브랜드 원칙 위반** — "은혜가 가득한" 은 신앙을 전제로 한 표현입니다.
   VisitHolyKorea 는 *"신앙을 앞세우지 않고 쉼과 걷기를 먼저 말한다"* 가 원칙인데,
   프롬프트에 브랜드를 안 넣었으니 모델이 알 도리가 없었습니다.

---

### v2 수정 — 플랫폼 규격을 숫자로 못 박았다

"짧게" 대신 **숫자**로 적었습니다. "짧게" 는 모델마다 해석이 다릅니다.

```
[플랫폼] 인스타그램 — 캡션 150자 내외 + 해시태그 10개 내외
- caption: 150자 내외의 한국어 캡션. 첫 문장에서 시선을 잡습니다.
- 줄바꿈은 쓰지 않고 한 덩어리로 씁니다.
- hashtags: 해시태그 10개. '#' 를 포함하고 띄어쓰기 없이 씁니다.
- 해시태그는 넓은 것(#여행)과 좁은 것(#성지순례)을 섞습니다.
```

여기에 **응답 형식을 JSON 스키마로 강제**했습니다.
캡션과 해시태그를 한 덩어리 문자열로 받으면 글자 수를 셀 수 없습니다.
따로 받아야 규격을 검증할 수 있습니다.

```python
"schema": {"caption": STRING, "hashtags": ARRAY[STRING]}
```

X 는 한 가지를 더 손봤습니다. 제한이 280자인데 프롬프트에는 **240자**라고 적었습니다.

> 모델은 상한을 넘기는 쪽으로 실수합니다. 여유를 두면 넘겨도 한도 안에 들어옵니다.

---

### v3 최종 — 브랜드와 금지 규칙을 넣었다

v2 는 규격은 맞췄지만 "은혜가 가득한" 류의 표현이 남았습니다.
브랜드 칸과 공통 규칙을 넣어 막았습니다.

```
[브랜드]
VisitHolyKorea — 한국 가톨릭 성지 208곳을 안내하는 순례 웹·모바일 서비스.
신앙을 앞세우지 않고 '쉼과 걷기'를 먼저 말한다. 차분하고 경건하되 무겁지 않게,
낯선 사람에게도 문턱이 낮게. 메인 컬러는 딥 네이비 #1E3A8A.

[공통 규칙]
- 한국어로 씁니다.
- 사실이 아닌 수치나 일정을 지어내지 않습니다.
- 종교를 권하는 표현은 쓰지 않습니다. 누구나 걸을 수 있는 곳으로 소개합니다.
```

## v1 대 v3 — 같은 주제, 같은 모델

| 항목 | v1 초안 | v3 최종 | 규격 |
| --- | --- | --- | --- |
| 인스타 캡션 | 172자 | **134자** | 150자 내외 ✅ |
| 인스타 해시태그 | 5개 | **10개** | 10개 내외 ✅ |
| 블로그 본문 | 435자 | **709자** | 500자 이상 ✅ |
| 블로그 소제목 | **0개** | **4개** | 3개 이상 ✅ |
| X 길이 | 101자 | 127자 | 280자 이내 ✅ |
| 종교 권유 표현 | **있음** ("은혜가 가득한") | 없음 | ✅ |
| 브랜드 언급 | 없음 | 있음 | ✅ |

v3 인스타그램 출력:

> 선선한 바람이 부는 가을, 복잡한 마음을 비우고 조용히 걷기 좋은 길을 찾고 계신가요.
> 깊어가는 계절의 풍경을 마주하며 온전히 나에게 집중하는 산책 같은 순례를 떠나보세요.
> 누구나 편안하게 발걸음을 옮길 수 있는 고요한 쉼터가 되어드릴게요.

"누구나 편안하게" 가 브랜드 원칙을 그대로 반영했습니다.

## 아직 남은 문제 — v4 로 고칠 것

프롬프트를 고쳐도 **완전히는 안 잡히는 것**이 있습니다. 숨기지 않고 적어 둡니다.

### 제목의 숫자와 본문 개수가 어긋난다

A안(친근) 블로그 출력:

> 제목: **가을에 걷기 좋은 한국의 아름다운 성지순례길 3곳**
> 소제목: 도입 / 서소문 / 솔뫼 / 마무리 → **실제 소개한 성지는 2곳**

B안(전문) 은 3곳(서소문·솔뫼·여주)을 제대로 냈습니다. 같은 프롬프트인데 갈렸습니다.

**v4 에서 넣을 규칙:**

```
- title 에 숫자를 쓸 경우, 그 숫자만큼의 장소 소제목이 sections 에 있어야 합니다.
- 도입과 마무리 소제목은 그 숫자에 포함하지 않습니다.
```

다만 프롬프트만으로는 보장되지 않습니다. **세는 쪽이 확실합니다.**
지금도 글자 수·해시태그 수는 코드가 세고 있으므로
([`pipeline.check_format`](../social_content/pipeline.py)), 여기에 같은 방식으로 붙이면 됩니다.

> **배운 것: 프롬프트로 부탁하고, 코드로 확인한다.**
> 규격을 프롬프트에만 맡기면 지켜졌는지 알 수 없습니다.

### 이미지 프롬프트는 영어로 옮겨야 한다

한국어 주제를 이미지 생성 API 에 그대로 넘기면 엉뚱한 그림이 나옵니다.
A2-1 과제에서 `"20-30대 여성"` 을 인물 사진 요청으로 읽어 **사람 사진**이 나온 적이 있습니다.

그래서 이 워크플로우는 이미지 단계를 두 번에 나눕니다.

```
[한국어 주제] → LLM("무엇을 그릴지 영어 20단어로") → [영어 장면] → 이미지 API
```

이때도 한글이 섞여 오면 버리고 실패로 처리합니다
([`pipeline.build_image_prompt`](../social_content/pipeline.py)).

실제로 받은 영어 장면:

```
A peaceful autumn stone path winding through golden and red maple trees
toward a quiet historic chapel under a deep navy sky.
```

브랜드 메인 컬러(딥 네이비)가 `deep navy sky` 로 장면에 들어간 점이 눈에 띕니다.
브랜드 칸을 프롬프트에 넣은 효과가 이미지 단계까지 이어졌습니다.

## 플랫폼별 최종 프롬프트 전문

실제 코드가 만드는 문자열입니다. `{}` 부분이 실행 시 채워집니다.

### 공통 뼈대

```
당신은 소셜 미디어 콘텐츠 에디터입니다.

[브랜드]
{brand}

[주제]
{topic}

[플랫폼] {platform.name} — {platform.limit_note}
{platform.rules}

[톤앤매너]
{TONES[tone]}

[공통 규칙]
- 한국어로 씁니다.
- 사실이 아닌 수치나 일정을 지어내지 않습니다.
- 종교를 권하는 표현은 쓰지 않습니다. 누구나 걸을 수 있는 곳으로 소개합니다.

[출력 형식] 지정된 JSON 만 출력합니다.
```

### 플랫폼별 `rules` 칸

| 플랫폼 | rules |
| --- | --- |
| 인스타그램 | 캡션 150자 내외 · 줄바꿈 없이 한 덩어리 · 해시태그 10개 · 넓은 것과 좁은 것을 섞기 |
| 블로그 | 제목 한 줄 · 소제목 3~4개 · 각 소제목마다 body · 합쳐서 500자 이상 · 감탄사로 분량 채우지 않기 |
| X | **240자 이내** (제한 280자에 여유) · 해시태그 2~3개 · 핵심 하나만, 나열 금지 |

### 톤앤매너 칸

| 톤 | 지시 |
| --- | --- |
| `friendly` | 친근하고 말 걸듯이. 반말은 쓰지 않되 '~해요' 체로 다정하게. |
| `professional` | 차분하고 정보 중심으로. '~합니다' 체로 신뢰감 있게. |

---

## 정리 — 프롬프트 설계 원리 4가지

1. **숫자로 적는다.** "짧게" 는 모델마다 다르게 읽습니다. "150자 내외" 는 같게 읽습니다.
2. **상한에는 여유를 둔다.** 280자 제한이면 240자라고 적습니다. 모델은 넘기는 쪽으로 틀립니다.
3. **출력 형식을 쪼갠다.** 캡션과 해시태그를 한 덩어리로 받으면 셀 수 없습니다.
4. **브랜드를 넣지 않으면 브랜드 톤이 나오지 않는다.** 모델은 알 도리가 없습니다.

그리고 무엇보다 — **프롬프트로 부탁하고, 코드로 확인합니다.**
