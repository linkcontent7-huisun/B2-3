## 4. 기능 요구 사항

### 입력 및 트리거

| 요구 | 상태 | 비고 |
| --- | :---: | --- |
| 주제/키워드를 입력받는 방식 | ✅ | 대화형 `input()` — 빈 값이면 다시 묻는다 |
| 입력 시 워크플로우가 트리거 | ✅ | `--topic` 옵션으로 비대화형 실행도 가능 |

### 플랫폼별 텍스트 생성

| 요구 | 상태 | 실제 결과 |
| --- | :---: | --- |
| 최소 3개 플랫폼 | ✅ | 3개 |
| 인스타그램 — 짧은 캡션 + 해시태그 10개 내외 | ✅ | 캡션 134자 · 해시태그 10개 |
| 블로그 — 500자 이상 + 소제목 구조 | ✅ | 본문 709자 · 소제목 4개 |
| X — 280자 이내 | ✅ | 127자 |
| 톤앤매너가 플랫폼별로 조정 | ✅ | 톤 2종을 프롬프트의 별도 칸으로 분리 |

**규격은 부탁만 하지 않고 코드가 셉니다.** 어긋나면 결과에 `⚠️` 로 표시합니다
([`pipeline.check_format`](../social_content/pipeline.py)).

### 이미지 생성

| 요구 | 상태 | 비고 |
| --- | :---: | --- |
| 이미지 생성 AI 로 주제에 맞는 대표 이미지 | ✅ | 1024×1024 PNG |
| 소셜 미디어에 활용 가능한 품질 | ✅ | 사람·글자·워터마크 없음 |

한국어 주제를 이미지 API 에 그대로 넘기면 엉뚱한 그림이 나오므로,
**LLM 이 영어 장면을 먼저 쓰고 그것만 이미지 API 로 넘깁니다.**

### 결과 저장

| 요구 | 상태 | 비고 |
| --- | :---: | --- |
| 텍스트와 이미지를 노션 등 협업 도구에 저장 | ✅ | `콘텐츠.md` 가 노션이 그대로 읽는 마크다운 |
| 플랫폼별로 구분되어 저장 | ✅ | 톤 → 플랫폼 2단 구조 |

> 완전 자동 업로드(노션 API 토큰 연동)는 붙이는 자리만 비워 두었습니다.
> 토큰 없이도 워크플로우 전체가 돌아가야 하기 때문입니다 ([`워크플로우.md`](워크플로우.md) 참고).

| 요구 | 상태 | 비고 |
| --- | :---: | --- |
